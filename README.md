# MineLauncher 1.0.2

Лаунчер Minecraft: Java Edition для Windows x64. Тёмная и светлая темы, официальные версии Mojang, Fabric / Forge / NeoForge, модпаки и контент Modrinth, собственные инстансы, проверка и восстановление файлов, резервные копии, серверный браузер, статистика, Discord Rich Presence и автообновление.

Написан на Electron + Node.js. Протокол Mojang реализован самостоятельно в `electron/core`: манифест версий, библиотеки с правилами ОС, нативы, ассеты (включая legacy/virtual), аргументы JVM и игры, log4j-конфиг, наследование профилей загрузчиков. Из runtime-зависимостей используется только `adm-zip`.

## Что нового

- **1.0.2**: кнопки «Скачать лаунчер» и GitHub в карточке Discord, автообновление выбирает установщик, а не портативную сборку; проприетарная лицензия.

- **Обслуживание**: проверка SHA-1, восстановление файлов, переустановка загрузчика, сброс инстанса, анализ крашей, очистка старых логов и `.part`, подсчёт занятого места, бэкапы с восстановлением.
- **Контент Modrinth**: моды, наборы ресурсов и шейдеры; установка зависимостей, обновление, поиск конфликтов, импорт файлов и drag-and-drop.
- **Собственные инстансы**: отдельная папка, свой загрузчик, экспорт и импорт `.zip`.
- **Модпаки**: обновление установленных сборок без удаления, отдельные миры и конфиги.
- **Сеть**: докачка `.part`, ограничение скорости, системный или ручной прокси, зеркало BMCLAPI, диагностика узлов.
- **Обновления**: проверка HTTPS-канала или GitHub Releases, скачивание и запуск `.exe`-установщика.
- **Интерфейс**: русский и английский языки, тёмная/светлая тема, 6 акцентных цветов.
- **Дополнительно**: серверный браузер с ping и MOTD, статистика запусков, Discord Rich Presence, экспорт/импорт настроек и миров.

## Возможности

- Список всех версий Mojang: релизы, снапшоты (включаются в настройках), старые альфы и беты.
- Fabric, Forge и NeoForge: выбор версии игры в отдельной группе списка, установка загрузчика при первом запуске.
- Modrinth: поиск модпаков, установка `.mrpack`, обновление, отдельная папка инстанса, автоматическая установка нужного загрузчика.
- Офлайн-аккаунт с корректным UUID (MD5 от `OfflinePlayer:<ник>`).
- Вход Microsoft по device code flow с обновлением токена.
- Загрузка клиента, библиотек, нативов и ассетов с проверкой SHA-1 и докачкой.
- Автоопределение Java в системе (PATH, JAVA_HOME, реестр, Program Files, `runtime` игры).
- Автоустановка JRE от Mojang под нужную версию игры (8, 16, 17, 21, 25).
- Настройка памяти, дополнительных аргументов JVM, своего разрешения окна.
- Консоль с выводом лаунчера и игры в реальном времени; лог пишется в файл.
- Отмена запуска и остановка игры.

## Модовые загрузчики

В выпадающем списке версий есть группы **Fabric**, **Forge**, **NeoForge**, **Модпаки** и **Инстансы**. Для загрузчиков выбирается последняя поддерживаемая версия; профиль запуска устанавливается автоматически при первом запуске.

- **Fabric** — профиль берётся из Fabric Meta, установщик не нужен.
- **Forge** — скачивается официальный installer с `maven.minecraftforge.net` и запускается с `--installClient`.
- **NeoForge** — installer скачивается с зеркала CreeperHost (официальный `maven.neoforged.net` используется как резервный).
- Профили загрузчиков разрешаются через `inheritsFrom`: библиотеки и аргументы родительской ванильной версии объединяются с загрузчиком, дубликаты classpath убираются в пользу версии загрузчика.
- Для установки Forge/NeoForge нужна Java. Лаунчер сначала проверяет её наличие и только потом скачивает установщик.
- Переустановить загрузчик можно в окне **Обслуживание** без переустановки всего инстанса.

## Модпаки и контент

Источник — открытый API [Modrinth](https://modrinth.com), ключ не нужен. CurseForge не поддерживается.

- Поиск по названию, установка последней опубликованной версии `.mrpack`.
- Модпак распаковывается в `<папка игры>\modpacks\<slug>`; библиотеки, ассеты и JRE общие для всех версий.
- `overrides/` и `client-overrides/` распаковываются в папку инстанса, файлы модов скачиваются по списку из `modrinth.index.json`.
- Загрузчик (Fabric/Forge/NeoForge) и его версия определяются из `dependencies` модпака.
- Установленный модпак появляется в группе **Модпаки**; его можно обновить с сохранением миров и настроек.
- Кнопка **Контент** открывает поиск модов, наборов ресурсов и шейдеров для выбранного инстанса или модпака. Зависимости Modrinth устанавливаются автоматически.
- Конфликты загрузчиков, отсутствующие зависимости и файлы вне учёта лаунчера отображаются в отчёте **Конфликты**.
- Файлы `.jar` и `.zip` можно перетащить в окно лаунчера — они попадут в текущий инстанс или модпак.
- Модпаки Quilt пока не поддерживаются. Модпаки только с серверными модами могут не запуститься без клиентских файлов.

## Собственные инстансы

Инстанс — это отдельная папка `<папка игры>\instances\<slug>` с собственными модами, конфигами, мирами и настройками Java.

- Создание, выбор версии Minecraft и загрузчика, заметки.
- Экспорт в `.zip` и импорт обратно; при импорте проверяется `instance.json` и небезопасные пути.
- Сброс удаляет моды, конфиги, логи и (по желанию) миры, не затрагивая остальные версии.
- Бэкапы содержат моды, конфиги, ресурсы, шейдеры и миры; хранятся в `<папка игры>\backups`.
- Проверка и восстановление файлов работают для ванильных версий, загрузчиков, инстансов и модпаков.

## Требования

- Windows 10/11 x64. Linux, macOS и ARM64 не поддерживаются.
- Node.js 22.12+ и npm — только для запуска из исходников и сборки `.exe`.
- Интернет: первый запуск качает клиент и ассеты (для 26.3 это ~500 МБ ассетов + ~40 МБ клиента + библиотеки). Модпаки качают свои файлы дополнительно.
- Java не обязательна: лаунчер скачает JRE Mojang сам. Для Forge/NeoForge Java нужна до установки, её тоже можно скачать из лаунчера.

## Запуск из исходников

```powershell
npm.cmd install
npm.cmd start
```

`npm.cmd` вместо `npm` нужен, потому что PowerShell по умолчанию блокирует `npm.ps1` (Execution Policy). В cmd.exe или Git Bash можно обычный `npm start`.

Если Electron не скачался при установке (пустой `node_modules/electron/dist`), выполните:

```powershell
node node_modules\electron\install.js
```

```powershell

```

Результат в `dist/`:

| Файл | Что это |
| --- | --- |
| `MineLauncher-Setup-1.0.2.exe` | Установщик NSIS: ярлыки, выбор папки установки |

## Подпись кода

Подпись не обязательна для работы, но без неё Windows SmartScreen показывает предупреждение. electron-builder автоматически читает переменные окружения:

```powershell
$env:CSC_LINK = 'C:\secure\minelauncher.pfx'
$env:CSC_KEY_PASSWORD = 'пароль-сертификата'
npm.cmd run dist
```

`CSC_LINK` также принимает URL, `file://`, base64-строку или `data:` URI. Для CI положите `.pfx` в секрет `CSC_LINK` (base64), а пароль — в `CSC_KEY_PASSWORD`. Переменные `WIN_CSC_LINK` / `WIN_CSC_KEY_PASSWORD` работают аналогично. Сертификат EV/HSM настраивается через параметры electron-builder `win.signtoolOptions` или `win.azureSignOptions`; в текущей конфигурации они не заданы.

## Автообновление

В настройках укажите **канал обновлений** — HTTPS-адрес JSON-фида или страницу GitHub Releases.

Прямой JSON:

```json
{
  "version": "1.0.2",
  "downloadUrl": "https://example.com/MineLauncher-Setup-1.0.2.exe",
  "notes": "Что нового",
  "sha256": "необязательно",
  "publishedAt": "2026-11-16T00:00:00Z"
}
```

GitHub:

```text
https://github.com/owner/repo
```

Лаунчер запросит `api.github.com/repos/owner/repo/releases/latest`, выберет `.exe` из assets и предложит скачать. Ссылка в прямом фиде должна вести на `.exe`; допускается только HTTPS. После скачивания установщик запускается, а лаунчер закрывается. Тихая установка и подпись обновления не выполняются.

Проверка выполняется при старте (если включено) и вручную в настройках. Баннер обновления также показывает прогресс загрузки.

## Вход через Microsoft

В лаунчер не встроен Azure Client ID: каждый пользователь регистрирует своё приложение. Это бесплатно и занимает пару минут.

1. Откройте [portal.azure.com](https://portal.azure.com) → **Microsoft Entra ID** → **App registrations** → **New registration**.
2. Имя любое, Supported account types — **Personal Microsoft accounts** (или «Accounts in any organizational directory and personal Microsoft accounts»).
3. Redirect URI не нужен. Нажмите **Register**.
4. На странице приложения скопируйте **Application (client) ID**.
5. Перейдите в **Authentication** → **Advanced settings** → **Allow public client flows** → **Yes** → **Save**.
6. В лаунчере: **Аккаунт** → вставьте Client ID → **Войти через Microsoft**.
7. Откроется страница `microsoft.com/link`, введите код из окна лаунчера и подтвердите вход.

Refresh-токен хранится в `config.json` в открытом виде — как и в большинстве лаунчеров. Не передавайте этот файл никому. Экспорт настроек не включает токен и профиль Microsoft.

## Discord Rich Presence

Rich Presence включается автоматически при старте лаунчера — отдельной галочки нет. Клиент подключается к локальному IPC Discord, переподключается каждые 15 секунд и молча ждёт, если Discord не запущен.

Для карточки активности нужен **Application ID** — идентификатор приложения Discord. Он не выдаётся лаунчером и не генерируется кодом: это публичный номер приложения, которое вы один раз регистрируете под своим Discord-аккаунтом.

1. Откройте [discord.com/developers/applications](https://discord.com/developers/applications) → **New Application**.
2. Назовите приложение `MineLauncher` — это имя увидят в Discord.
3. На странице **General Information** скопируйте **Application ID**.
4. Вставьте ID в **Настройки → Discord Rich Presence** или в константу `BUILTIN_CLIENT_ID` в `electron/core/discord.js` и пересоберите `.exe`.

Поле в настройках хранится в `config.json` как `discordClientId`. Если оно пустое, используется `BUILTIN_CLIENT_ID`; в этой сборке там уже прописан Application ID `1571927876310274119`, поэтому Rich Presence работает без настройки. Поле нужно только для переопределения своим приложением. ID не является секретом, его можно хранить в репозитории. Иконки и название карточки задаются в настройках приложения Discord; без ассетов отображаются только название приложения, детали и время.

В карточке профиля показываются две кнопки: **Скачать лаунчер** (последний релиз GitHub) и **GitHub** (репозиторий). Discord ограничивает такие кнопки: не больше двух, только `https://`-ссылки и метка до 32 символов. Кнопки видны в профиле пользователя, а не в компактной карточке в списке участников.

## Скрипты

```powershell
npm.cmd start              # запуск лаунчера
npm.cmd run dry-run        # проверка метаданных и аргументов без скачивания
npm.cmd run regression     # локальные тесты 1.0 без сети и реальных данных
npm.cmd run e2e            # полный тест: JRE + запуск игры
npm.cmd run modpack-e2e -- 1KVo5zza  # установка модпака в тестовую папку
npm.cmd run make-icon      # пересборка build/icon.png и build/icon.ico
npm.cmd run pack           # распакованная сборка в dist/win-unpacked
npm.cmd run ui-smoke       # UI-тест собранного приложения через CDP
npm.cmd run dist           # NSIS + portable .exe
```

`e2e` принимает аргументы: компонент JRE, цель запуска, секунды до остановки игры.

```powershell
node scripts\e2e.js java-runtime-epsilon 26.3 30
node scripts\e2e.js java-runtime-epsilon fabric:26.3 30
node scripts\e2e.js java-runtime-epsilon forge:26.3 30
node scripts\e2e.js java-runtime-epsilon neoforge:26.3 30
node scripts\e2e.js java-runtime-epsilon modpack:fabulously-optimized 60
node scripts\e2e.js jre-legacy 1.5.2 30
```

Папку для теста можно задать через `ML_E2E_DIR` (по умолчанию `%TEMP%\mclauncher-e2e`), реестры загрузчиков, модпаков и инстансов — через `ML_E2E_DATA` (по умолчанию `%TEMP%\mclauncher-e2e-data`).

`ui-smoke` по умолчанию запускает `dist\win-unpacked\MineLauncher.exe` с изолированным `APPDATA` и `ML_SMOKE=1`. Для проверки исходников:

```powershell
$env:ML_SMOKE_EXE = 'node_modules\electron\dist\electron.exe'
npm.cmd run ui-smoke
```

Скриншоты `smoke.png`, `smoke-modpacks.png`, `smoke-instances.png`, `smoke-settings.png` сохраняются в корень проекта.

## CI

`.github/workflows/build.yml` собирает Windows-сборку на `windows-latest` при push тега `v*` и вручную. Шаги: `npm ci`, локальная регрессия, `npm run dist`, загрузка артефактов. При наличии секретов `CSC_LINK` и `CSC_KEY_PASSWORD` сборка подписывается. Для тега создаётся GitHub Release с установщиком и portable-версией.

## Ограничения

- Только Windows x64. Linux, macOS и ARM64 не тестировались и не поддерживаются.
- Модпаки Quilt не поддерживаются; CurseForge не поддерживается.
- Автообновление требует собственного HTTPS-фида и `.exe`; проверка подписи обновления не выполняется.
- Нет скинов и плащей: лаунчер не загружает и не отображает их.
- Старые версии (1.5.2 и древнее) запускаются, но их серверы ресурсов у Mojang давно отключены — часть звуков и языков может отсутствовать, это нормально.
- Офлайн-аккаунт не подходит для серверов с `online-mode=true`.
- Версии до 1.6 требуют Java 8; лаунчер сам подберёт подходящую и предложит скачать.
- Без сертификата Windows SmartScreen может показать предупреждение. Инструкция по подписи — выше.

## Частые проблемы

**«Не найдена Java 25+»** — нажмите кнопку установки в ошибке или в настройках: лаунчер скачает JRE Mojang в папку игры. Системная Java не нужна. Для Forge/NeoForge установка загрузчика без Java не начнётся.

**Forge/NeoForge не устанавливается** — проверьте консоль: установщик пишет причину. Убедитесь, что в папке игры есть `launcher_profiles.json` (лаунчер создаёт его сам) и достаточно места на диске. Если официальный maven NeoForge недоступен, используется зеркало CreeperHost.

**Игра падает сразу после запуска** — откройте **Обслуживание → Анализ краша** или посмотрите консоль и `logs\launcher.log`. Частые причины: слишком мало памяти, старый драйвер видеокарты, несовместимая Java (для старых версий нужна 8), конфликт модов в модпаке. Кнопка **Проверить файлы** найдёт повреждённые и отсутствующие файлы, **Восстановить** скачает их заново.

**Не скачиваются ассеты или файлы модпака** — выполните **Настройки → Диагностика сети**. Проверьте прокси, лимит скорости и режим зеркала. Загрузки повторяются автоматически, `.part`-файлы докачиваются с места обрыва.

**Обновление не находится** — канал должен быть HTTPS, а версия в фиде — выше установленной. Для GitHub укажите ссылку на репозиторий, а не на отдельный релиз. Убедитесь, что в релизе есть `.exe` asset.

**Discord не подключается** — проверьте Application ID и что Discord запущен. Лаунчер повторяет подключение раз в 15 секунд; при отсутствии Discord ошибка не блокирует игру.

**Ошибка входа Microsoft** — проверьте, что Client ID скопирован полностью и в Azure включён «Allow public client flows». Для аккаунтов без лицензии Minecraft вход не пройдёт.

**Конфликты модов** — откройте **Контент → Конфликты**. Лаунчер покажет моды другого загрузчика, отсутствующие зависимости, дубликаты и файлы, добавленные вручную. Файлы вне учёта не обновляются автоматически, но продолжают работать.

## Лицензия

MineLauncher — проприетарное программное обеспечение. Исходный код опубликован для ознакомления, но не для повторного использования: копирование, форки, изменение и распространение сборок без письменного разрешения правообладателя запрещены. Полный текст — в файле [LICENSE](LICENSE).

Использовать лаунчер по назначению, запускать игру и передавать неизменённые официальные сборки со ссылкой на этот репозиторий можно свободно и бесплатно.

Сторонние библиотеки (Electron, adm-zip и другие) остаются под своими лицензиями.
